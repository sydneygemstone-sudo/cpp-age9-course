🚀 开课三步

1. 起服务器（在你的 Mac 上，终端里跑）

cd ~/cpp-course
node tools/make-seed.js --nickname "孩子的昵称" > server/seed.json
node server/server.js --port 8099 --seed server/seed.json --fresh
⚠️ 最后那个 --fresh 不能省 只要你课前彩排过一次，server/data/ 里就会留下上一轮的会话。没有 --fresh 的话，服务器会默认沿用它，你新改的孩子昵称和 A 档种子会被忽略——孩子打开看到的是彩排时用的名字。
课中万一要重启服务器（比如误关了终端），这时反而不要加 --fresh，去掉它才能接着上一轮、不丢孩子的进度。
✅ 启动后先看这几行再发链接 服务器会把这堂课实际用的会话打出来，核对昵称和档位对不对： 
本次课堂使用的会话：
  来源     种子文件 server/seed.json
  昵称     孩子的昵称
  档位     A
  主题     robot
要是这里显示「沿用上一轮的 latest.json」并跟着一段 ⚠️，说明种子没生效，按它的提示加 --fresh 重来。
⚠️ 昵称记得改 现在种子里写的是占位的「闪电小队长」。上面第二行换成孩子自己起的昵称，作品卡标题会用它。孩子已经开始上课后就别再跑这两条命令了。

2. 学生链接（抄给他，或微信发给他）

http://<你的电脑IP>:8099/index.html

服务器启动时会自己把这个地址打印出来。如果当天 Mac 的 IP 变了，以启动时打印的为准。

3. 你自己的教师端

http://localhost:8099/teacher.html

PIN 8888。这页是内部页面，别投屏给孩子。

📋 开课前逐项确认

  • 两台电脑连的是同一个 WiFi
  • 学生的 MacBook Air 上装了 Chrome（课件只保证 Chromium 内核，别赌 Safari）
  • 终端里跑了上面第 1 步，看到「服务器已启动」和一串链接
  • 第一次跑时 macOS 可能弹「是否允许 node 接受传入网络连接」→ 点允许，否则学生连不上
  • 在学生的 Air 上打开链接，确认第一屏是「你好，XXX！」而不是要求填昵称、选世界
    （看到填昵称页 = 种子没送到，把服务器停掉、重跑第 1 步、让他刷新）
  • 你的教师端能进，顶部能切到「第1课」页签
  • 课上先自己点一次「🧪 真实C++验证」，确认能盖章（今天实测通过，当天再确认一次网络）

🛠 环境部署：为什么不放在这节课

时间对不上 第 1 课教案是 60 分钟 8 个活动排满的。而装编译器那一步（Command Line Tools）要下载好几个 GB，实测常见等待是 20 分钟到 1 小时，中途还可能要管理员密码。硬塞进课上，大概率是孩子盯着进度条、课上不完。

我的建议：环境部署做成学生自助的 14 页 slides，让他在课前或课后自己走一遍。你不用碰他的电脑。

http://<你的电脑IP>:8099/setup.html

slides 覆盖：认识访达 → 下载 VS Code → 装进应用程序 → 首次打开 → 装中文界面 → 认识终端 → xcode-select --install → 等待 → g++ --version 验收 → 建工作文件夹 → 手敲第一个 energy.cpp → 编译运行看到 6 → 作业。

作业已经在里面了 最后两页：把 energy.cpp 只改一个数字让它输出 10（改之前先在纸上算）；加分题是故意删个分号，认一认编译器生气的样子。下次课带来："你改的哪个数字？为什么？"
英文是怎么渗透的 课件本身保持全中文，一个字没动。英文只出现在 slides 每页底部的小词卡里，一页 2–3 个，全是他当下正在屏幕上看到的那几个词：file / folder / open / save / install / run / error / line / int / cout / terminal / version。最后一页汇总成一张词汇表。

🔌 出问题怎么办

情况会发生什么你怎么做
学生连不上链接 浏览器转圈或打不开 确认同一 WiFi；确认防火墙放行了 node；用服务器启动时打印的那个 IP
服务器中途挂了 孩子端照常上课，进度存在他本机浏览器里，一点不丢 不用慌。你的教师端会看不到实时状态——要调档或解锁提示，直接去他电脑上开 teacher.html 点一下（10 秒）
断网 / 编译服务不可用 显示「⚠️ 概念演示——真实编译暂不可用」，绝不会假装成功 照实告诉孩子，照常上课。作品卡照常保存，只是没有印章，下次联网补一次验证即可
孩子想重玩前面的关卡 全课完成后回不到活动 1–7 课上别答应。真要重来，课后用教师端「导出会话 JSON」留档后再「删除会话」

🚫 课上不要碰的两个东西

1. 教师端的「删除会话」——课中绝对不要点 在跨机模式下它现在是坏的（今天实测）：孩子那边的数据会被清空，但服务器上的旧数据留着，之后孩子端的上传会被一直拒绝。课后要清数据的话，先「导出会话 JSON」留档，然后直接把服务器关掉、删掉 server/data 目录，比点那个按钮干净。
2. 不要同时开两个儿童端 比如学生电脑上开了一个、你又在自己电脑上开了一个儿童端页面。两个都会往服务器写整份会话，会互相把对方的进度整包覆盖掉，孩子做过的活动和证据会直接消失。儿童端全程只留一个（学生那台），你这边只开教师端。

这两条都是今天实测出来的，不是理论风险。绕开它们就不会碰到。

📄 课后：家长报告要改再发

⚠️ 自动生成的草稿不能直接发给家长 今天实测生成了一份完整草稿，有三个地方会让家长看了糊涂，需要你改：
  • 标题写的是「一、试听概况」「试听日期」——这节是第 1 课，不是试听。报告模板还是按试听课写的。
  • 「三、本次学到的内容」整段写成「既有基础：进入任务即能独立完成，无需现场教学」——字面意思是这节课孩子什么都没学到，正好说反了。
  • 「二、已观察能力」里引用的任务描述是从课件里截断的半句话（「能量站送来四张命令卡，可它们全散了！把命令卡排成正确的队伍，……」），读起来很怪。

教师端本来就是「生成草稿 → 逐条编辑 → 确认 → 打印」的流程，草稿只是给你省打字的。报告正文里没有出现档位字样（E/S/A）也没有分数，这条产品红线是守住的——但如果你自己在编辑时写了「A 档」「95 分」，系统不会拦你，别写。

🚧 我没做的事（如实说明）

  • 没有真的用两台物理机器对跑。双端同步是在这台 Mac 上用两个互相隔离的会话 + 真实 HTTP 往返验证的，学生端首屏和 8 关闭环是用真实浏览器（全新 profile）验证的。周六前值得花 5 分钟用他的 Air 真连一次——上面 checklist 里那条。
  • 8 关闭环是机器点的，不是人上的课。脚本能把 8 关全点完、数字全对，但它不会念讲稿、不会判断孩子听没听懂。"老师照着教案从头讲一遍"这件事只有你能做。
  • 「删除会话」的修复没做，只是让你绕开它。真要修得改动同步层，周六前动它风险比收益大。
  • 家长报告只改了说明、没改生成器。草稿里"试听概况""既有基础"那几处措辞还是原样，需要你在教师端手工改。
  • 没改课件的 UI。"极简、字少"本来就是它的既有设计（面板按活动动态出现、同屏最多 2 个高亮按钮，是写进技术契约的红线），所以我没有重建学生端。
  • 没在学生的 Air 上装过环境。slides 里的步骤基于 macOS 标准流程和这台 Mac 的实际环境写的，第一次走可能会遇到我没预料到的弹窗——遇到了拍给我，我改 slides。
  • 三个主题世界只保留了机器人世界（按你的要求）。宠物乐园和探险王国的内容还在课件里，只是种子把主题定死成机器人世界，孩子不会再看到选择页。
