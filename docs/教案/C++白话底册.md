## 1. 程序按顺序跑

**是什么**：一段程序就是一列命令。电脑从最上面一行开始，做完一行才做下一行，从不跳着做、也从不同时做（我们这门课的范围内）。交换两行的顺序，中间过程一定不同，最终结果也可能不同。

**比喻**：排队过安检——一个人过完，下一个才能上；泡面步骤——先烧水、再放面、再加调料，顺序换了味道就不对。

**在课里哪一屏**：第 1 课活动 2「命令排队」（排四张命令卡、交换顺序看能量路线）；试听课「第一场小胜利：让搭档动起来」排图块也是它。每个活动里的「👣 单步」按钮就是"顺序"的可视化——按一次走一行。

**孩子问倒你了怎么办**：
- "电脑那么快，为什么不一起做？"——"它快是快在'一条一条做得飞快'，快到你以为是同时。但按「单步」放慢就露馅了：真的是一行一行来。"
- "顺序换了结果一样啊？"（活动 2 恰好如此）——"最终一样是碰巧，中间路过的数不一样。让程序自己回答：交换后按运行，盯着能量条的中间值。"

## 2. int 变量：有名字的盒子

**是什么**：变量是程序用来**记东西**的一小块空间，有名字、有当前值。`int` 是变量的一种，专门装整数（3、10、-2 这种，不带小数点）。`int energy = 3;` 读作：造一个装整数的盒子，起名 energy，先放进 3。关键性质：**盒子任何时刻只装一个"现在的值"**，装新的，旧的就没了；变量必须先建立（先有 `int energy = …` 这行），后面才能使用它。

**比喻**：**有名字的盒子** / 贴了标签的存钱罐。罐子上写着"energy"，里面的钱数会变，但罐子永远只有"现在有多少"这一个事实——它不写日记，不记历史。

**在课里哪一屏**：第 1 课活动 3「能量盒」整屏都在演它（旧值淡出、新值住进来）；右栏「📦 变量卡」面板就是所有盒子的实时照片。试听课「能量卡片会变身：认识变量」首次出现。

**孩子问倒你了怎么办**：
- "3、7、6 都在盒子里吗？"——"任何时候只装一个。让程序自己回答：单步走一行，看变量卡上是不是永远只有一个数。"
- "int 是什么的缩写？"——"integer，英文'整数'。程序里还有装别的东西的盒子，比如只装真假的（第 2 课见），这期先认识装整数的。"
- "为什么非要起名字？"——"盒子多了不起名字就拿错了。名字是给人看的，起 energy 还是 apple 电脑都不在乎，但你的同伴在乎。"

## 3. 赋值：`=` 不是"等号"，是"装进去"

**是什么**：`energy = energy + 4;` 里的 `=` 叫**赋值**，动作分三步：①先读出等号右边用到的旧值（energy 现在是 3）；②算出右边的结果（3+4=7）；③把结果装进等号**左边**的盒子（energy 变成 7，旧的 3 被覆盖）。永远是**先算右边，再装回左边**。所以"energy = energy + 4"在程序里完全合法——它不是数学宣言，是一个动作。

**比喻**：**先算右边再装回左边的传送带**——货物（计算结果）永远从右往左送，送进左边那个盒子。数学的等号是天平（两边平衡），程序的等号是传送带（单向装货）。

**在课里哪一屏**：第 1 课活动 3（检查点反复考"这一行读到的旧值是几"）、活动 4（直接考"`=` 是什么意思"，正确选项是"把右边算出的结果，存进左边的盒子"）、活动 8（让孩子讲出读→算→存三步）。

**孩子问倒你了怎么办**：
- "数学老师说 x = x + 4 无解！"——"数学老师没错，程序也没错——它俩用同一个符号干两件不同的事。程序里这句读作'把 energy 加 4 后装回去'。以后遇到真正的'比较相等'，程序写两个等号 `==`，就是为了跟这个装东西的 `=` 分开。"
- "为什么先算右边？"——"因为要装进盒子的是'结果'，不算完没东西可装。就像先把菜炒好，才能装盘。"

## 4. std::cout：机器人的喇叭（输出）（宠物乐园：小狗搭档的扩音器／探险王国：探险搭档的号角）

**是什么**：`std::cout << energy;` 的意思是"把 energy 现在的值显示到屏幕上"。它**只报告，不修改**——喊完之后盒子里的数一格不变。屏幕上只会出现被它喊过的值；程序中间出现过、但没被喊过的值（比如那个 7），屏幕上永远看不到。读法：cout 念"C-out"（意思是往外输出），`<<` 像两个小箭头，把东西"推"向屏幕。

**比喻**：**机器人的喇叭**（宠物乐园：小狗搭档的扩音器／探险王国：探险搭档的号角） / 体重秤——秤只报告体重，站一百次也不会让你变重。

**在课里哪一屏**：第 1 课活动 4「代码透视」专门考它（"删掉 cout 那行，盒子里的数会变吗？"——不变）；活动 6 靠它对答案（"屏幕为什么只打印 6 不打印 7？"）。右栏「🖥 机器人说（输出）」面板显示的就是它喊出的内容（宠物乐园主题该面板显示「小狗搭档说（输出）」，探险王国显示「探险搭档说（输出）」）。

**孩子问倒你了怎么办**：
- "std 和那两个冒号是什么？"——"std 是'标准工具集'的门牌，`std::cout` 意思是'标准工具集里的那个 cout 喇叭'。当成一个完整名字整体记就行，不用拆开背。"
- "`<<` 为什么朝左？"——"箭头指向谁，东西流向谁——数据从右边流向 cout（屏幕）。认方向就行。"
- "我想把中间的 7 也打出来！"——"好主意，让程序自己回答：在第二行后面也加一行 `std::cout << energy;`（A 档可在自由编辑里试，其他档口头讲原理即可）。"

## 5. 运算优先级：先乘除，后加减

**是什么**：一行里有多种运算时，程序和数学课规则一样：先算乘（`*`）和除（`/`），再算加减；有括号先算括号。`energy = energy + shield * 2;` 里先算 `shield * 2`，再加到 energy 上——**不是**从左往右一路算过去。

**比喻**：乘号是插队的 VIP——排队再靠前，也得先让 VIP 办完。想改变顺序就发"括号通行证"：`(energy + shield) * 2` 就变成先加后乘。

**在课里哪一屏**：第 1 课活动 3 的 A 档（`energy = energy + shield * 2;`，预测题专门考先乘后加）、活动 5 的 A 档（`boost * 2` 槽位）；试听课「能量预测站」里有一题优先级。E/S 档孩子第 1 课不会碰到，被问到再讲即可。

**孩子问倒你了怎么办**：
- "为什么不从左往右算？"——"世界各地的程序员约好了跟数学课一致，这样一段代码谁看都是同一个意思。想强行从左往右？加括号，程序永远听括号的。"
- 孩子算出 8（(3+1)×2）而不是 5（3+1×2）——别讲理论，写下两个式子让他各算一遍，再让程序跑一遍对答案。

## 6. 整数除法：int 盒子装不下小数

**是什么**：两个整数相除，结果**只保留整数部分，小数直接扔掉**（向零截断，不是四舍五入）：`7 / 2` 得 3，不是 3.5；`1 / 2` 得 0。原因出在**除法本身**：只要参加运算的两个数都是整数，这个除法就按"整数除法"的规矩进行，算的当场就把小数部分截掉了——**不是**"先算出 3.5、再装进 int 盒子被挤掉"。对照着看就明白：`7.0 / 2` 里有一个数带小数点，除法就按小数除法算，结果是 3.5。另一件事要分开讲：如果把一个小数结果**再存进 int 盒子**（比如 `int x = 7.0 / 2;`），那是**另一次转换**——先按小数除法算出 3.5，存入 int 时再被截成 3。两层截断发生在不同时刻：一层在"算除法"时，一层在"装盒子"时，别混成一件事。

**比喻**：分披萨只数整块——7 块披萨 2 个人分，每人拿 3 整块，剩那一块切碎的不算数。是"分的时候"就只按整块分（整数除法的规矩），不是"装盘时"才把半块扔掉。

**在课里哪一屏**：第 1 课的题目里**不出现**除法（事件只有加、减、乘）；它可能冒出来的场景是 A 档孩子在「自由编辑」里自己写除法，或有基础的孩子主动追问。第一次被问到时能答上来就行，不用主动教。

**孩子问倒你了怎么办**：
- "为什么 7/2 不是 3.5？"——"因为 7 和 2 都是整数，除法就按整数除法算，小数部分当场被截掉——不是装盒子时才丢的。让程序自己回答：自由编辑里写 `std::cout << 7 / 2;` 真实验证一下，看它吐 3；再写 `std::cout << 7.0 / 2;`，它就吐 3.5——只要有一个数带小数点，除法就换成小数除法的规矩。"
- "那想要 3.5 怎么办？"——"要换一种能装小数的盒子（叫 double）。这期课用不到，先知道'有这种盒子'就行。"

## 7. 比较符：`>`、`>=`，以及 `==` 和 `=` 的天壤之别

**是什么**：比较符提出一个"是不是"的问题，答案只有真或假：
- `energy > 5`：energy **严格大于** 5 吗？（正好 5 → 假）
- `energy >= 5`：energy **大于或等于** 5 吗？（正好 5 → 真）
- `energy == 5`：energy **正好等于** 5 吗？（**两个等号**才是比较！）
- 同理还有 `<`、`<=`、`!=`（不等于）。
`>` 和 `>=` 的差别只在"正好压线"那一个数上——这正是程序出 bug 的高发区（叫边界问题）。**一个 `=` 是装东西（赋值），两个 `==` 才是比一比**，写错是全世界程序员都犯过的经典错误。

**比喻**：**岔路口的检票员**手里拿着规则牌：`>` 的牌子写"必须超过 5，正好 5 不算"；`>=` 的牌子写"满 5 就行"。`=` 是把票塞进盒子，`==` 是检票员核对票面——动作完全不同。

**在课里哪一屏**：第 2 课全程——活动 2「人工舱门游戏」（孩子扮检票员判开/不开）、活动 3「条件透镜」（把 `energy >= 5` 放进真假检测器亮绿灯红灯）、活动 5「边界错误侦探」（门在正好 5 格时不开，把 `>` 修成 `>=`）。试听课「智能舱门的秘密：差一点点的规则」首次露面。

**孩子问倒你了怎么办**：
- "> 和 >= 不是差不多吗？"——"就差'正好压线'那一个数。让程序自己回答：把能量分别设成 4、5、6 各跑一遍，看哪次两个符号给出不同答案。"（就差 5 那次。）
- "为什么等于要写两个等号？"——"因为一个 `=` 已经被'装东西'占用了。程序员只好给'比较'发了个双胞胎符号 `==`。记法：比较是两边互相看，所以有两条横线成对出现。"

## 8. bool：只有真假两面的硬币

**是什么**：`bool` 是另一种盒子，里面**只能装两个值之一**：`true`（真）或 `false`（假）。所有比较的答案都是 bool。`bool hasKey = true;` 就是造一个叫 hasKey（有没有钥匙）的盒子，装进"真"。

**比喻**：**只有真假两面的硬币**——不是正面就是反面，没有立起来这一说。

**在课里哪一屏**：第 2 课，主要在 A 档扩展（`bool hasKey = true;` 配合 `&&` 做双条件门）；「条件透镜」屏上的绿灯 ✓（真）/ 红灯 ✗（假）就是 bool 值的可视化；右栏变量卡遇到 bool 会直接显示"真 ✓ / 假 ✗"。E/S 档孩子不要求会写，看懂真假灯即可。

**孩子问倒你了怎么办**：
- "为什么要专门发明真假盒子？数字 1 和 0 不行吗？"——"行得通但容易糊涂。专门的真假盒子让代码一眼能读懂：hasKey 是 true，就是'有钥匙'，不用猜 1 代表啥。"
- "bool 怎么念？"——"就念'布尔'，是一位数学家的名字，他专门研究真和假的运算。"

## 9. if-else：岔路口检票员

**是什么**：`if` 让程序第一次学会"自己做决定"：

```cpp
if (energy >= 5) {
    std::cout << "OPEN";
} else {
    std::cout << "CHARGE";
}
```

读法："如果括号里的问题答案为真，就走上面花括号 `{}` 里的路；不然（else），走下面那条。"三个要点：①条件只在程序**执行到 if 那一行的那一刻**被检查一次，不是一直在后台盯着；②**两条路永远只走一条**，另一条整个被跳过，一行都不执行；③花括号 `{}` 把一条路上的若干行捆成一包。

**比喻**：**岔路口的检票员**——查一次票（算一次条件），指一个方向；你走了左边，右边那条路今天就跟你无关。

**在课里哪一屏**：第 2 课核心——活动 4「两条道路」（单步走 if/else，没走的那条**整条变灰**）、活动 7「设计自己的规则」（孩子自选门槛做自己的舱门规则）。第 1 课不出现（活动 5 教师卡的"进阶追问"会预告它）。

**孩子问倒你了怎么办**：
- "else 那边是不是也偷偷跑了一下？"——"一行都没跑。让程序自己回答：第 2 课的屏幕会把没走的路涂灰给你看；真要较真，在两条路里各放一个喇叭，看屏幕只喊出一句。"
- "条件会不会过一会儿再检查一次？"——"不会，检票员只在你路过闸机那一刻查一次。想再查一次？程序得再走到一次 if（以后学了循环就能做到）。"
- "花括号忘了写会怎样？"——分两种情况，别混着讲："第一种：写了 `{` 却忘了配上 `}`（**不配对**）——编译器会退回来报错，翻译过来就是'括号没配对'，这正是让真编译器当检查员的好处。第二种：一条路上只有一句话时，把 `{}` **成对省略**（写成 `if (energy >= 5) std::cout << "OPEN";`）——这是**完全合法的 C++，编译器不会报错**。我们这门课约定永远成对保留花括号，不是语法要求，而是防坑：以后想在这条路上多加一句话时，没有花括号的话新句子会溜到 if 外面去，程序照跑但走错路，这种 bug 很难发现。"

## 10. &&：两道门都要开

**是什么**：`&&` 读作"并且"，把两个小问题拼成一个大问题：`energy >= 5 && hasKey` 意思是"能量够 **并且** 有钥匙"。**两边都为真，整体才为真**；任何一边是假，整体就是假。它还有个小脾气叫**短路**：机器从左往右检查，**左边一旦是假，右边那半句完全不检查**——反正整体已经注定是假，何必再查。

**比喻**：**两道门都要开才能过**——保险柜要同时插两把钥匙；少一把，门就不开。短路就是：**第一道门锁住了，第二道门保安连看都不看**。

**在课里哪一屏**：第 2 课 A 档扩展（双条件舱门；「条件透镜」A 档有一题双灯判断）。方案明确规定：`&&` 只在加速档或孩子主动追问时出现，**不是全员必学**——E/S 档孩子没见过它是正常的，别主动加戏。

**孩子问倒你了怎么办**：
- "一边真一边假，算真还是假？"——"假。'并且'很严格，两个都点头才算数。让程序自己回答：能量 7 但钥匙 false，跑一遍看门开不开。"
- "两边它都检查吗？"——"从左往右查：左边是真，才去看右边；左边是假，右边**完全不检查**——这叫短路。就像第一道门锁住了，第二道门就不看了。"
- "有没有'或者'？"——"有，写作 `||`，两边有一个真就行。这期课不要求，认识一下不吃亏。"

## 11. 什么是编译（以及"真实 C++ 验证"到底干了什么）

**是什么**：电脑其实读不懂我们写的 C++ 文字，它只认机器指令。**编译器**是翻译官：把整份代码通读一遍、检查有没有语法错误，全部通过后翻译成电脑可直接执行的程序——这个过程叫**编译**；然后才谈得上**运行**。课件里的动画是"演习模拟器"；点「🧪 真实C++验证」时，课件把完整程序通过网络发给一台真正的编译器（真 g++），对方编译、运行、把真实输出寄回来。**真实编译器的输出是最终事实**——模拟和真实一致，说明我们手算对了。

**比喻**：写了一封外语信（代码），寄给专业翻译官（编译器）；翻译官要么指出"第 4 行拼写有问题"退回来，要么翻译成对方看得懂的话并带回回信（运行结果）。

**在课里哪一屏**：第 1 课活动 6「真实 C++ 验证」整屏；活动 2、4、5 跑完也能点验证；活动 7 有专属按钮「🧪 用真实C++验证我的故事」（成功会给作品卡盖"已通过真实 C++ 验证"印章）。第 2 课活动 6 用真实输出驱动舱门开关动画。**断网时**一律显示"⚠️ 概念演示——真实编译暂不可用"，绝不假装成功——如实告诉孩子"今天没连上真编译器，下次补盖章"即可，课程照常进行。

**孩子问倒你了怎么办**：
- "编译和运行有什么区别？"——"编译是翻译加检查，运行是照着翻译好的指令真干活。先翻译，后干活，顺序不换。"
- "模拟器和真编译器谁说了算？"——"真编译器。模拟器是我们做的慢动作教具，正常情况俩人答案一样；万一不一样，以真编译器为准，然后叫我一起来看（那多半是发现了一个值得研究的问题）。"
- "为什么要等好几秒？"——"代码坐网络快递去了另一台服务器，编译、运行、再寄回来，几秒钟已经很快啦。"

## 12. 报错怎么读（课件会翻译成中文）

**是什么**：代码写错时，编译器不会爆炸，只会**退回一份错误报告**。原始报告是英文术语（教师端可展开原文），但课件会自动翻译成中文人话卡片，格式是"**哪里出了什么事 + 建议先检查哪里**"，例如："编译器在第 4 行附近没有找到分号。先检查第 3 行的结尾。"课件认识的常见错误类型：缺分号、用了没建立的变量、引号没关上、括号/花括号不配对、少写了内容、类型不匹配、把 `==` 写成了 `=`、程序跑太久、输出太多。

**比喻**：编译器是**免费的检查员**，不是判官——它圈出错的位置，从不扣分。报错越早出现越省事，等于有人替你把坑提前踩了。

**在课里哪一屏**：正常流程不会遇到（预置程序都是对的）；出现在 A 档「自由编辑」孩子自己写代码时，以及第 2 课 A 档的"= 与 == 找错"。看到报错卡片照着念就行；卡片里的行号指的是**完整程序**的行号，可点「🔭 查看完整程序」对照找。

**孩子问倒你了怎么办**：
- 孩子看到报错慌了——先念这两句："出错是工程师每天都会遇到的事""编译器是在帮我们指路"。然后照卡片提示只改一处，再验证一次。
- "它说的第 4 行怎么数？"——"点「🔭 查看完整程序」，按弹窗里的行号数——报错说的是完整程序的行号，头上的 #include 也算一行。"
- 报错卡片看不懂 / 没给出翻译——"编译器说了一些悄悄话，我们把原文记下来（教师端能看到），先检查最近改过的那一行，多半就是它。"

## 13. 「聚焦代码 vs 完整程序」是怎么回事

**是什么**：课件平时只给孩子看**聚焦代码**——真正在干活的那几行（比如四行能量程序）。但真实的 C++ 程序必须穿一套固定"外壳"才能编译，点「🔭 查看完整程序」或切「完整程序」标签就能看到全貌：

```cpp
#include <iostream>

int main() {
    int energy = 3;
    energy = energy + 4;
    energy = energy - 1;
    std::cout << energy;
    return 0;
}
```

外壳三件套的一句话版：
- **`#include <iostream>`**：把"输入输出工具箱"装进程序——`std::cout` 这个喇叭就是从这箱子里拿出来的。
- **`int main() { … }`**：主程序入口，电脑从这扇门进来开始逐行执行；全世界的 C++ 程序都从 main 开始，名字不能改。
- **`return 0;`**：结尾向电脑报告"顺利做完了"，0 是"一切正常"的暗号。

课程立场：**不要求孩子在第 1 课背这三行**，但必须让他知道聚焦代码住在一段真实完整程序里——我们没有发明假语法。

**比喻**：聚焦代码是"家里的人"，外壳是"房子"——`#include` 是先备好的工具间，`int main() {` 是大门，`return 0;` 是出门时说的那句"我走啦，没事"。快递员（电脑）只认大门，不会从窗户进。

**在课里哪一屏**：任何有代码的活动都能点「🔭 查看完整程序」（全档位、只读弹窗）；S/A 档代码台多一个「完整程序」标签；第 1 课活动 6 发射前专门带孩子看一眼（"真正发出去的是完整版"）。

**孩子问倒你了怎么办**：
- "为什么平时不给我看完整的？"——"先学开车再学发动机盖下面的东西。外壳每个程序都长一样，先把会变的那几行玩明白，外壳看多了自然就脸熟了。"
- "main 是什么意思？"——"英文'主要的'。一个程序可以有很多零件，但大门只有一扇，就叫 main。"
- "不写 return 0 会怎样？"——"这期课的程序里它是标配，先照写。真省略了 main 也有默认处理，但我们先按完整礼仪来。"

## 术语速查表（课中忘词就翻这页）

| 术语 | 一句话人话 | 快捷比喻 |
|---|---|---|
| 程序 | 一列从上到下依次执行的命令 | 排队过安检 |
| 变量 | 有名字、装着"现在的值"的存储格 | 有名字的盒子 |
| `int` | 只装整数的变量类型 | 装整数的盒子 |
| 赋值 `=` | 先算右边，把结果装进左边的盒子 | 单向传送带（不是天平） |
| `std::cout` | 把值显示到屏幕，只报告不修改 | 机器人的喇叭（宠物乐园：扩音器／探险王国：号角） / 体重秤 |
| `<<` | 把数据推向屏幕的小箭头 | 往喇叭里送话 |
| 运算优先级 | 先乘除后加减，括号最大 | 乘号是 VIP，括号是通行证 |
| 整数除法 | 两个整数相除按整数除法算、向零截断（7/2=3；7.0/2=3.5 是小数除法） | 分披萨只数整块 |
| 函数机器 | 输入 → 处理 → 输出的规则机器（"参数/返回值"是它们在第 5 课的正式名字） | 左边塞纸条，右边吐新纸条 |
| 输入 / 处理 / 输出 | 放进机器的数 / 肚子里的加工规则 / 吐出来的数 | 进口—肚子—出口 |
| bug | 程序实际做的事和想要的规则不一致 | 藏在代码里的小虫子 |
| 边界测试 | 专挑门槛前一格、正好门槛、后一格各试一遍 | 4、5、6 三张卡片逐张过闸机 |
| `>` / `>=` | 严格大于 / 大于或等于（差别在压线值） | 检票员的两块规则牌 |
| `<` / `<=` | 严格小于 / 小于或等于（差别同样在压线值） | 检票员的另一对规则牌 |
| `==` | 比较两边是否相等（两个等号！） | 检票员核对票面 |
| 条件 | 一个只有"真/假"两种答案的问题 | 检票员手里的问题 |
| `bool` | 只能装 true（真）/ false（假）的类型 | 只有真假两面的硬币 |
| `if / else` | 条件为真走上路，否则走下路，只走一条 | 岔路口检票员 |
| `&&` | 并且：两边都真才算真；左边为假右边完全不检查（短路） | 两道门都要开；第一道锁住第二道就不看了 |
| `{ }` 花括号 | 把一条路上的几行代码捆成一包 | 打包带 |
| 编译 | 翻译官通读代码、查错、译成机器指令 | 寄信给翻译官 |
| 编译错误 | 翻译官退回的"哪里没看懂"报告 | 免费检查员的圈注 |
| 聚焦代码 | 只显示干活的核心几行 | 家里的人 |
| 完整程序 | 核心行 + 固定外壳（能真实编译的全文） | 人 + 房子 |
| `#include <iostream>` | 装上输入输出工具箱 | 备好工具间 |
| `int main()` | 程序唯一的入口 | 大门 |
| `return 0;` | 结尾报告"一切顺利" | 出门说"我走啦，没事" |
| 单步 | 一次只执行一行（课件按钮「👣 单步」） | 慢动作回放 |
| 真实 C++ 验证 | 把完整程序发给真编译器跑，返回真实结果 | 请裁判盖章 |
| 概念演示 | 断网时的标记：结果来自模拟，非真实编译 | "裁判今天没到场" |
| 调试 | 预测→运行→找差距→只改一处→再验证 | 侦探破案流程 |
