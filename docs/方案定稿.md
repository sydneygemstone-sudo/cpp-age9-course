# 《九岁儿童 C++ 互动课程》推进方案（定稿存档）

> 来源：ChatGPT 对话「C++互动课程方案设计」定稿方案，2026-08-04 抓取存档。
> 本文件是本项目的**事实源（source of truth）**，任何实现冲突以本文件为准。
> 注：原文中的表格在抓取时被展平为制表符分隔的行，内容完整，阅读时按列理解。

本方案以需求包为交付合同：**1 节试听/诊断 + 12 节正式课；中文优先的互动 HTML 学习站；兼顾儿童体验、证据化诊断、教师兜底、真实 C++ 路径与适龄 AI 使用。** 学生当前水平未知不构成阻塞，系统通过现场分支和前两节课复核处理不确定性。

## 一、总体判断与产品拍板

### 1. 方向成立，但真正产品不是"浏览器里的 C++ 编译器"

建议继续推进，但产品定位应明确为：

**一套面向九岁儿童的一对一、诊断自适应、可视化 C++ 编程实验室。**

核心价值的优先级应当是：

1. 孩子能预测程序会发生什么；
2. 孩子能看到变量、执行顺序和分支如何改变场景；
3. 老师能观察、追问、降阶和记录证据；
4. 真实 C++ 编译用于验证学习真实性；
5. AI 用于提示、解释和审阅，而不是代写；
6. 最后才是动画美术、编辑器完整度和技术炫技。

### 2. 一期应做的不是"完整课程"，而是三段纵向样片

一期只完成：

- 试听/诊断课
- 正式第 1 课：命令、状态与变量
- 正式第 2 课：条件与程序决策

这三段必须共同证明：

- 试听能产生证据化判断；
- 第 1 课能真正教学，而不是继续考试；
- 第 2 课能读取前一课状态、提高难度、形成连续学习；
- 模拟执行和真实 C++ 编译能协同；
- 非资深 C++ 教师可以独立运行课程。

### 3. 第 1、2 课不从 Hello World 开始

建议顺序：

- 第 1 课：《机器人能量站》——顺序执行、变量、赋值、输出
- 第 2 课：《智能舱门》——比较、布尔条件、if/else

Hello World 可以作为"完整代码透视"中的一个小知识点，但不应成为孩子的第一道门槛。

这样安排的原因是：

- 变量变化能立即驱动能量条、机器人和场景动画；
- 条件判断天然形成游戏规则；
- 两课能直接承接试听中的状态追踪、变量意识和逻辑诊断；
- 前两课已经能做出一个小型互动作品；
- 函数在试听中只做"输入—处理—输出"的概念接触，正式语法延至第 5 课，避免过载。

### 4. 试听只能给出临时路径

试听结束可以向家长给出推荐起点，但应标记为：已观察事实 / 初步判断 / 待第 1、2 课复核。

正式路径在第 2 课后再确认；第 6 课还应再进行一次轻量复核。

## 二、最容易偏掉的七个地方

偏差	可能后果	本方案的纠正
把"网页能运行 C++"当作主要产品	编译器投入巨大，教学效果反而薄弱	教学状态机为主，真实编译为真实性校验层
把试听做成数学和语法测试	会数学的孩子被误判为会编程，电脑不熟的孩子被低估	使用"预测—执行—解释—现场教学—迁移"闭环
一次试听就固定路线	对孩子过度推断	试听临时分流，第 1、2 课继续采证
为三档水平制作三套课程	内容和维护成本接近三倍	一个共同课程脊柱，每个任务配置三种支架

## 四、试听/诊断课完整闭环

### 4.1 试听课的基本循环

每个核心任务均遵循：**先预测 → 再操作或运行 → 再解释 → 必要时现场教学 → 换一个新情境迁移**

诊断重点不是第一次是否答对，而是：孩子怎样思考；接受何种提示后能够推进；能否解释；能否把刚学到的东西用到新题；遇到错误时会不会检查和修正。

### 4.2 三种现场支架

这三档是教师内部使用的交互支架，不向孩子显示"低、中、高级"。

支架	适用表现	孩子主要操作
E：探索支架	白纸水平、电脑操作不熟、理解需要具象化	拖拽指令、点选、口头解释、一次只追踪一个变量
S：标准支架	接触过图形化编程或能理解基本状态变化	填空、拼代码、修改数字和条件、少量输入
A：加速支架	接触过 Python/C++，能独立解释或写小程序	自由编辑、双变量、边界测试、开放调试

**自动建议与人工覆盖规则**

- 连续两项任务在无提示或轻提示下正确，并能解释：建议上调一档；
- 连续两项在概念提示后仍无法推进：建议下调一档；
- 单题表现不得触发固定分流；
- 电脑操作慢，不自动降低计算思维等级；
- 老师可随时覆盖系统建议，覆盖原因记入记录。

### 4.3 60 分钟试听蓝图

时间	模块	孩子看到和做什么	主要证据
0–4 分钟	进入任务世界	选择机器人、宠物或探险主题；回答"你以前最喜欢做过什么作品"	兴趣、表达、既往经验、电脑熟悉度
4–9 分钟	第一场小胜利	将"前进—捡电池—开门"三个图块排顺序，动画立即执行	顺序意识、拖拽操作、解释能力
9–16 分钟	能量预测	预测能量变化；先用简单加减，再加入一题运算优先级	数学与符号基础，但不据此单独分流
16–25 分钟	状态与变量	看着 energy 卡片逐行变化；选择合适变量名；改变一行后重新预测	状态追踪、变量意识、旧值与新值
25–33 分钟	智能舱门与找错	判断能量为 5 时，规则 energy > 5 是否开门；修改为 >=	条件、边界意识、调试与解释
33–43 分钟	函数机器	先教"充电机：输入 2，处理 +3，输出 5"；再迁移到新的护盾机器	输入—处理—输出、模式迁移
43–51 分钟	场景分解	将"拿钥匙、检查能量、开门、救出宠物"拆成步骤和规则	问题分解、遗漏检查、条件意识
51–56 分钟	动态挑战	E 用图块；S 补代码槽；A 调试一段短 C++ 或补函数返回值	当前上限、独立性、代码经验真实性
56–60 分钟	孩子讲解与反馈	孩子选择最喜欢的任务，向机器人"讲明白"一个概念	元认知、兴趣来源、表达和下一课主题

**试听中的自然了解方式**：不弹出正式问卷，而是在场景之间穿插：
- "你以前做过最满意的程序是什么？它会做什么？"
- "那个作品是你自己打开软件做，还是老师已经帮你准备好了？"
- "程序不动时，你通常先看哪里？"
- "你更想做游戏、机器人、故事、宠物还是数学挑战？"
- "平时电脑主要用来玩游戏、看视频、画画还是做作品？"
- "你喜欢别人先演示一次，还是自己先试？"

## 五、诊断维度、评分与证据模型

### 5.1 不使用单一总分

系统输出一个能力向量，而不是"82 分""优秀"这类伪精确结论。

统一评分尺度：

等级	含义
N	本次未观察，不得解释为不会
0	已示范并给予逐步帮助后仍未建立当前概念
1	在明确步骤或仿照范例下完成
2	在相同结构的新题中独立完成
3	能解释、迁移、自我检查或提出更优方法

每条分数同时记录支持等级：S0：无提示；S1：重复题意或中性追问；S2：概念提示；S3：给出部分结构；S4：演示一个步骤。

速度不直接计分；自行发现并修正错误是正向证据。

### 5.2 诊断维度

维度	核心观察	代表任务	对路径的影响
D1 数学与符号基础	四则运算、括号、比较符号	能量预测	只决定数学支架，不得单独提升编程路径
D2 顺序执行	是否理解命令逐行发生	排列指令、改变顺序	核心路径指标
D3 状态追踪	能否追踪变量当前值	能量逐行变化	核心路径指标
D4 变量抽象	能否把"变化的量"理解为有名字的状态	energy、score	核心路径指标
D5 条件与规则	能否理解规则只在条件成立时执行	智能舱门	第 2 课难度依据
D6 模式识别与分解	能否从场景提取步骤、重复和规则	救援任务分解	项目能力指标
D7 函数输入—处理—输出	能否理解同一机器处理不同输入	充电机与迁移题	第 5 课支架依据
D8 调试与解释	是否查看状态、定位行、说明原因	边界错误、逻辑错误	核心路径指标
D9 学习后迁移	现场教学后能否解决表面不同的新题	新函数、新变量或新场景	最重要的路径指标之一
D10 独立性与坚持度	卡住后是否继续尝试、是否接受提示	全程观察	决定教学节奏，不贴性格标签
D11 求助与元认知	能否描述"我哪里不懂"、选择合适提示	提示按钮与课末讲解	决定 AI 使用训练
D12 电脑操作熟练度	键盘、鼠标、浏览器、输入与运行	全程观察	决定交互方式，不直接代表编程能力

兴趣单独记录为类别，不打能力分：游戏规则；故事和角色；机器人与机械；建造和创造；数学挑战；调试解谜；社交展示。

### 5.3 路径推荐规则

**探索线**：满足以下任一情况时临时推荐：
- D2、D3、D4、D8、D9 中有三个或更多维度为 0–1；
- 迁移任务仍需逐步示范；
- 电脑操作显著妨碍表达，需要先使用图块和单步动画。

**标准线**：适合：
- 能独立完成熟悉结构的状态追踪；
- 经一次概念提示可以迁移；
- 能使用代码槽或修改短代码；
- 对错误能够作出基本解释。

**加速线**：只有在以下证据同时出现时推荐：
- 能独立追踪两个或以上状态；
- 能解释赋值、分支或函数中的至少一个概念；
- 能自行编辑或调试短文本程序；
- 新情境迁移达到 2–3；
- 既往作品经验可由实际任务验证，而不只是口述"学过"。

**两条重要限制**：数学表现好，不能直接升级路径；自称学过 C++，但只能复述语法、无法追踪状态，也不进入加速线。

### 5.4 证据记录格式

每条证据至少包含：

```
session_id
timestamp
activity_id
diagnostic_dimension
current_variant: E / S / A
task_prompt
child_action_or_quote
answer_or_code
attempt_count
support_level: S0-S4
outcome
self_correction: true / false
transfer_result
teacher_note
confidence: low / medium / high
```

不记录：连续键盘录像；麦克风录音；孩子真实姓名、学校、生日；与课程无关的完整聊天内容。

### 5.5 儿童即时反馈

儿童端不显示能力分数，而显示三部分：

**今天解锁的能力**，例如：
- 🧭 顺序导航员：能看出命令先后会改变结果；
- 🔋 能量管理员：能追踪变量变化；
- 🔍 错误侦探：发现规则边界的问题。

**今天真正学会的一件事**，由孩子选择或口头补全："变量不是一直不变的数字，它保存的是现在的状态。"

**下一次任务**，根据路径自动生成积极但具体的预告："下一次，你会给舱门写规则，让程序自己决定打开还是关闭。"

### 5.6 家长试听报告结构

1. **试听概况**：日期、时长、使用支架；孩子选择的兴趣主题。
2. **已观察能力**：每项必须带任务证据和支持等级；例如："在能量三步变化任务中，孩子无提示得到最终值，并能指出第二行读取的是修改前的能量。"
3. **本次学到的内容**：区分既有能力和现场学会的能力。
4. **兴趣与参与方式**：更喜欢预测、构建、调试、故事还是竞争；对何种反馈反应最好。
5. **当前边界**：使用中性描述；例如："面对两变量同时变化时，当前需要状态卡支持。"
6. **推荐起点**：探索、标准或加速；写明推荐依据和置信度。
7. **12 课预期成果**：完成可运行的 C++ 入门作品；能解释变量、条件、循环和函数；能独立进行基本测试与调试；能适龄使用 AI 寻求提示并验证回答。
8. **待复核假设**："是否能独立使用文本编辑器"；"既往 C++ 经验是否稳定"；"函数迁移是否能在间隔一周后保持"。
9. **家庭支持建议**：每周 5–15 分钟展示和讲解；不要求家长代写；让孩子解释程序为什么运行。

所有自动生成内容必须经老师确认后才能交给家长。

## 六、13 节弹性课程地图

**三种路径说明**

- E 探索线：图块、可视化、代码槽、较短作品；
- S 标准线：半开放文本代码、逐渐减少支架；
- A 加速线：自由编辑、更多状态、边界与扩展挑战。

三条线共享同一故事、概念和成果，不复制三套课程。

默认连续主题为：**《星际救援基地》**：编写程序帮助机器人管理能量、通过舱门、自动巡逻、使用工具、完成救援。孩子可以换成宠物、赛车、魔法或探险皮肤，但底层任务结构不变。

0 试听	程序是按顺序改变状态的规则；函数是输入—处理—输出机器	修复机器人、追踪能量、找规则错误、函数迁移；生成个人任务卡	D1–D12 初始画像	可选：画出最想制作的程序；核心诊断阶段不开放 AI	无依赖；E/S/A 动态切换

5 函数工厂	函数把任务包装成可重复使用的机器；参数是输入，返回值是输出	制作 charge()、heal() 或 calculateScore()	输入输出、函数调用、局部变量	画一个函数机器；AI 比较两个方案但不代写	依赖变量；E 调用现成函数，S 补函数体，A 自写函数
6 任务总指挥	大问题可以拆成若干有名字的小任务；每个函数只负责一件事	将救援过程拆为检查、移动、充电、开门等函数	分解质量、命名、调用顺序、局部状态	把一项家庭任务拆成函数；AI 只在孩子先提交方案后审阅	依赖函数；第 2 次路径复核点
7 背包装备库	一组同类数据可以放进集合；索引表示位置	查看、添加、遍历钥匙、电池和工具；制作背包界面	索引、空集合、顺序、循环结合	制作自己的三格背包设计；AI 生成边界测试	依赖循环；E 固定槽位，S 使用脚手架 vector，A 自由修改
8 小游戏规则引擎	变量、条件、循环、函数和集合可以协作形成完整规则	构建一轮可玩的救援小游戏；加入分数、生命和胜负	综合追踪、测试、调试策略	写三个测试情境；AI 只生成测试和审阅解释	依赖 1–7；S/A 可引入 while，随机数为扩展
9 真正的 C++ 工作坊	源代码经过编译形成可运行程序；报错是编译器提供的线索	查看完整 .cpp，导出并在真实工具链中运行；理解源代码→编译器→程序→输出	工具独立性、读错能力、迁移到站外环境	向家长解释编译流程；AI 只翻译真实编译器错误	E 继续浏览器真实编译，S 引导本地，A 可用终端
10 毕业作品设计	先定义目标、状态、规则和最小可玩版本，再写代码	从救援冒险、宠物状态机、积分挑战中选一项；形成项目卡和流程图	范围控制、分解、依赖意识	准备故事、规则和测试表；AI 只批评方案遗漏	依赖综合基础
11 毕业作品开发	一次实现一个可验证功能；不断运行和修正	完成核心循环、主要条件和函数；形成可玩 Alpha	独立调试、求助方式、代码解释	邀请家长测试并记录一个问题；AI 在孩子解释后做代码审阅	按个人路径控制代码规模
12 作品打磨与展示	程序完成不等于能解释；展示需要测试、整理和反思	修复问题、添加说明、完成最终作品和两分钟讲解	元认知、真实性、迁移与表达	无传统作业；保留作品、源码和成长卡	A 可扩展 struct、随机或多文件，但不作为核心要求

**明确不纳入十二课核心线的内容**：指针与地址运算；动态内存管理；模板；复杂面向对象设计；图形游戏引擎；多文件工程和构建系统；算法竞赛式题海。这些内容并非"不重要"，而是不适合作为九岁儿童十二课入门课程的主脊柱。

## 七、正式第 1 课详细互动样课

### 7.1 课名

《机器人能量站：命令怎样改变世界》

**本课可验收学习目标**：孩子能够：
- 说明程序会按顺序运行；
- 追踪一个变量的当前值；
- 理解赋值是"把计算结果存回变量"；
- 知道输出只是在展示状态，不会自动修改状态；
- 修改代码并预测结果；
- 至少完成一次真实 C++ 编译验证。

### 7.2 孩子看到的主界面

- 左侧：机器人、能量站和动态能量条；
- 中间：代码台；
- 右侧：变量卡、执行时间线和输出；
- 底部四个主要动作：先预测 / 单步运行 / 全部运行 / 真实 C++ 验证。

任何时刻主屏不超过两个高亮主按钮，避免操作拥挤。

### 7.3 核心代码

聚焦模式只显示：

```cpp
int energy = 3;
energy = energy + 4;
energy = energy - 1;
std::cout << energy;
```

"查看完整程序"透视模式再显示：

```cpp
#include <iostream>

int main() {
    // 聚焦代码位于这里
    return 0;
}
```

不要求孩子在第一课记忆 #include、main 和 return 0；但系统必须让孩子知道聚焦代码属于一段真实完整程序，而不是伪造语法。

### 7.4 60 分钟活动设计

时间	活动	互动与视觉	教师观察
0–5	返回任务世界	读取试听中选择的机器人和主题；显示"上次你修复了它"	是否记得变量或顺序概念
5–12	命令排队	拖动"获得 4 能量""使用 1 能量"；交换顺序后看结果	是否知道顺序会改变中间状态
12–22	能量盒	energy 以盒子形式显示；每行执行时旧值淡出、新值写入	是否把变量理解为当前值而非一串历史
22–34	代码透视	图块逐渐切换成 C++；点击某一行，场景突出对应动作	能否把可视化动作映射到代码
34–45	正好到达 10	给定起始能量和两次操作，让孩子修改数字达到 10	预测、尝试、调试、解释
45–50	真实 C++ 验证	生成完整源代码，提交真实编译；显示数值输出并与动画对照	是否理解模拟与真实运行的关系
50–56	我的改造	选择机器人皮肤、初始能量和事件，保存一个个人版本	是否能创造而非只复制

### 7.5 三档分支

**E 探索支架**：只改变数字；一次显示一个变量；代码与图块同步；允许口头预测；最多四行聚焦代码。

**S 标准支架**：自己输入数字和变量更新表达式；完成两次预测；找出一行逻辑错误；查看完整程序但不要求背诵。

**A 加速支架**：增加：

```cpp
int energy = 3;
int shield = 1;

energy = energy + shield * 2;
```

要求：追踪两个变量；解释右侧先计算、左侧后写入；可选比较 energy = energy + 2 与 energy += 2。

### 7.6 教师知识真相卡

教师必须能一键查看：

- `int energy = 3;`：建立一个整数变量并存入 3；
- `energy = energy + 4;`：先读取旧值，计算，再把新值写回；
- `=` 在这里是赋值，不是"左右永远相等"；
- `std::cout` 只输出，不改变变量；
- 程序通常从上向下执行，但以后会通过条件、循环和函数改变执行路线。

**常见误区**：认为变量同时保存 3、7、6 三个值；认为 energy = energy + 4 在数学上不成立，因此代码错误；认为所有行同时发生；认为输出命令会自动给机器人增加能量。

**降阶提示**：
- "先别看代码，只看盒子现在是几。"
- "右边先算完，会得到几？"
- "现在把这个结果放回左边的盒子。"
- 仍然困难时播放逐行慢动画。

**进阶追问**：
- "交换第二、三行后，最后值一样吗？中间过程一样吗？"
- "如果机器人不能出现负能量，程序还缺少什么规则？"

### 7.7 第 1 课可见成果

孩子保存一张作品卡：自选机器人；初始能量；三至五行代码；最终结果；一句自己的解释；"已通过真实 C++ 验证"标记。

## 八、正式第 2 课详细互动样课

### 8.1 课名

《智能舱门：让程序自己做决定》

**本课可验收学习目标**：孩子能够：
- 把条件理解为结果为"真或假"的问题；
- 预测 if/else 只会执行哪一侧；
- 区分 > 与 >=；
- 修改条件并测试边界；
- 使用上一课的 energy 状态制作一个有两个结局的小程序。

### 8.2 状态承接

进入第 2 课时自动读取：孩子的机器人和主题；第 1 课保存的初始能量；第 1 课路径和提示历史；孩子作品卡。

开场不是重新讲一套新故事，而是："你的机器人已经有能量了，现在它来到一扇会判断能量的智能舱门。"

这一步是证明产品不是一次性 Demo 的关键。

### 8.3 核心代码

```cpp
int energy = 5;

if (energy >= 5) {
    std::cout << "OPEN";
} else {
    std::cout << "CHARGE";
}
```

高级扩展：

```cpp
bool hasKey = true;

if (energy >= 5 && hasKey) {
    std::cout << "OPEN";
}
```

&& 只在加速线或孩子主动追问时出现，不作为所有学生的本课必学内容。

### 8.4 60 分钟活动设计

时间	活动	互动与视觉	教师观察
0–7	能量回忆	根据第 1 课代码预测当前能量，点击正确变量卡	间隔后的保持情况
7–15	人工舱门游戏	老师改变能量，孩子扮演舱门判断"开或不开"	条件作为规则的理解
15–25	条件透镜	将 energy >= 5 放进"真假检测器"；实时显示真/假	比较和边界
25–36	两条道路	单步运行 if/else；未执行的分支变灰	是否误以为两边都会执行
36–46	边界错误侦探	舱门在能量恰好 5 时不开；孩子发现 > 应改为 >=	调试、例子驱动思考
46–52	真实编译验证	编译不同输入，动画依据真实输出选择开门或充电	能否把真实输出与场景对应
52–57	设计自己的规则	选择能量门、年龄门、钥匙门或积分门，修改条件	迁移和创造
57–60	课末解释	回答："程序什么时候检查条件？为什么只走一边？"	心智模型是否稳定

### 8.5 三档分支

**E 探索支架**：从"能量够不够"图形问题开始；只编辑阈值数字；使用真/假灯和两条分支轨道；不要求输入花括号。

**S 标准支架**：补全比较符；修改完整条件；输入两组测试数据；解释 else 何时运行。

**A 加速支架**：两个条件；设计恰好等于边界的测试；调试可选语法问题：= 与 ==；> 与 >=；解释短路逻辑不作为必达要求。

### 8.6 教师知识真相卡

- 条件在执行到 if 时被计算一次；
- 条件结果只有真或假；
- 真时执行 if 块，假时执行 else 块；
- `>` 不包括相等，`>=` 包括；
- `==` 是比较，`=` 是赋值；
- 花括号包围一个代码块。

**常见误区**：认为两个分支都会先后运行；认为条件会一直在后台自动检查；忽略边界值；把"能量变化"与"检查能量"混为一件事。

**降阶提示**：
- "先把自己当成舱门，只回答真还是假。"
- "现在的能量是几？规则要求什么？"
- "真时走上面，假时走下面。"
- 使用恰好比阈值小 1、等于阈值、大 1 的三张卡。

### 8.7 第 2 课可见成果

一个可玩的"智能舱门"：至少两个输入结果；一条自定义规则；一个边界测试；一次真实 C++ 编译；一段孩子自己的解释；从第 1 课继承的机器人和能量状态。

## 十、浏览器内 C++ 技术路线

### 10.1 路线比较

路线	真实性	部署与响应	安全与离线	错误可读性	结论
纯 JS 教学模拟	能准确表达已定义概念，但不是任意真实 C++	部署最轻，响应即时	可离线；禁止使用 eval	可完全儿童化	必须保留，但不能冒充真实编译
预编译 C++ → WASM	运行的是已编译真实 C++，但不能直接编译孩子任意修改	首次需加载资源，之后运行快	可缓存并离线运行已编译内容	不会提供源代码编译错误	适合课程运行时和最终作品发布，不适合一期自由编译
浏览器内完整 Clang/LLVM 编译器	可实现真实源代码编译	编译器、标准库和文件系统资源重，冷启动和维护复杂	理论上可离线，但需要严格控制 Worker、内存和超时	原始错误复杂，仍需翻译	一期不做
受控远程编译服务	真实 C++ 编译和执行	依赖网络和服务端，通常有请求延迟	必须使用沙箱、资源限制、限流和隔离	可取得真实 stderr，再进行儿童化翻译	作为真实验证层
混合路线	概念可视化 + 真实编译校验	大部分操作即时，关键节点远程验证	无网仍可教学，有网时验证真实 C++	自定义提示与原始错误并存	主推荐

Emscripten 用于后续课程运行时、示范程序或教师审核后的最终作品发布，而不是在一期强行把完整编译工具链塞进儿童浏览器。Judge0 一类代码执行系统适合作为编译适配器的参考实现，接口应采用提交令牌和短轮询。Service Worker 可用于缓存静态课程资源；Web Worker 不是执行不可信代码的安全沙箱。

### 10.2 主推荐架构

```
儿童操作
   ↓
教学活动模型
   ├── 可视化状态执行器 → 即时动画
   ├── C++ 代码生成器 → 聚焦代码 / 完整代码
   ├── 证据记录器 → 路径建议 / 报告
   └── CompilerAdapter
          ↓
      自有服务端代理
          ↓
      Judge0 或受控容器编译服务
```

**前端建议**（如果现有仓库没有可复用栈）：React + TypeScript + Vite；SVG/CSS 动画，不引入大型游戏引擎；CodeMirror 6 或同等级轻量编辑器；内容定义使用 TypeScript/JSON；IndexedDB 保存会话和作品；Vitest 做状态和内容测试；Playwright 做三个路径的端到端验收。

**编译 API**：

```
POST /api/compile
request: activityId, source, stdin, mode: verify/free, sessionToken
response: status, stdout, stderr, compileOutput, exitCode, executionTime, compilerVersion
```

**安全约束**：API 密钥不得下发到浏览器；一期只允许单文件 C++；固定 C++17；不允许学生传入编译参数；禁止网络访问；限制 CPU 时间、内存、输出大小和输入大小；每会话限流；不持久化编译容器文件；超时后立即终止；编译器和沙箱版本必须可审计；学生源代码不得默认用于模型训练或长期保存。

**错误显示**：儿童端："编译器在第 4 行附近没有找到分号。先检查第 3 行结尾。"教师端可展开原始错误：error: expected ';' after expression。

一期至少支持翻译：缺分号；未声明变量；括号或花括号不匹配；引号未闭合；表达式缺失；类型不匹配；= 与 == 的可疑使用；超时或输出过多。

不得用 AI 凭空猜测编译错误；先读取真实编译器结果，再由规则或 AI 做解释。

## 十一、AI 助教机制与儿童边界

### 11.1 教学协议

孩子统一学习：**想一想 → 问提示 → 跑一跑 → 讲明白**

- 想一想：先提交预测或自己的思路；
- 问提示：AI 只给当前等级的提示；
- 跑一跑：通过模拟或真实编译验证；
- 讲明白：孩子解释为什么。

没有预测或第一次尝试时，不直接开放"帮我写代码"。

### 11.2 试听中的 AI 限制

核心诊断任务完成前，AI 默认关闭，以免污染基线。试听末尾可以设置一个单独任务观察：孩子会怎样向 AI 描述问题；是否直接索要答案；是否能判断 AI 的建议；是否会运行验证。这项结果单列为"AI 协作习惯"，不计入核心编程能力。

### 11.3 提示阶梯

等级	AI 可以做什么
H1	重述目标并提出一个问题
H2	指向相关变量、代码行或概念
H3	给出部分结构或排除一个错误方向
H4	给一个不同数字、不同场景的近似例子
H5	教师解锁后展示部分解法，并要求孩子补全和解释

默认不直接给完整最终程序。

### 11.4 AI 可以承担的角色

用另一种比喻解释；针对真实编译错误做适龄翻译；生成测试输入；检查孩子的解释是否与代码一致；指出可能需要检查的行；对孩子已经完成的代码提出一个改进建议；扮演展示观众提出问题。

### 11.5 AI 不得承担的角色

直接完成课堂挑战；在孩子未尝试前输出完整答案；自动替换孩子的全部代码；独立给出能力等级或家长评价；询问真实姓名、学校、地址、联系方式；开放网页搜索和与课程无关的自由聊天；把一次错误解释为能力或性格问题。

### 11.6 一期技术决策

一期必须先实现：确定性提示阶梯；教师预写解释；真实编译错误映射；HintProvider 接口。

实际 LLM 助教放在 feature flag 后：

```
HintProvider
├── RuleBasedHintProvider  // 默认、离线可用
└── LLMHintProvider        // 可选、教师开启
```

即使 LLM 服务失效，课程仍须完整可用。

**C. 第 1 课**：状态与变量可视化；单步、预测、运行和重置；三档挑战；个人作品保存；真实 C++ 验证；完整教师卡。

**D. 第 2 课**：读取第 1 课状态；条件和分支动画；边界找错；三档挑战；真实编译；第二次路径确认。

### 12.2 验收标准

**教育有效性**：试听核心维度均有直接证据或明确标记"N：未观察"；每个核心概念至少出现一次教学后迁移；不依靠数学总分决定路径；第 1、2 课各至少有三次"预测—运行—解释"循环；孩子无需在前 20 分钟书写完整程序；每课均产生可向家长展示的作品；第 2 课确实读取第 1 课状态，而不是视觉上假装连续。

**儿童体验**：进入活动后 90 秒内有第一次可见成功；单个界面不同时高亮三个以上主要操作；支持重置且不会因失败丢失课程进度；错误提示先解释动作，再显示工程术语；不使用只有颜色才能区分的反馈；动画和声音均可关闭。

**教师可运行性**：每项活动均包含：正确心智模型；正确结果；演示步骤；三个追问；常见误区；降阶提示；加速扩展。教师不查看源代码仓库，也能从头完成课程和报告。

**技术真实性**：标准样例在固定 C++ 环境真实编译；故意制造的语法错误能返回真实错误；概念模拟与真实编译在标准任务中结果一致；无法可视化的自由代码不会被假动画覆盖；编译器不可用时明确标注，不显示伪"验证成功"；浏览器端不包含编译服务密钥；请求具有超时、限流和输出限制。

**报告可信度**：自动报告区分"已观察、初步判断、待验证"；每项关键判断能回链到具体任务证据；教师确认前不能生成最终家长版；支持修改错误记录；不输出智力、人格或长期能力结论。

**QA**：至少完整跑通以下三名模拟学生：白纸学生（需要图块和多次提示）；图形化编程学生（能理解规则但不熟悉文本语法）；已有文本代码学生（能快速进入自由编辑和边界调试）。还需覆盖：中途上调路径；中途下调路径；教师人工覆盖；网络断开；编译超时；刷新后恢复；删除会话；生成和编辑报告。

### 12.3 开发顺序

- **G1 最小纵向切片**：先只做一个活动：能量预测 → 单步动画 → 生成 C++ → 真实编译 → 记录证据 → 教师查看。这条链路不通，不扩展其他页面。
- **G2 试听闭环**：扩展完整试听、动态分支、儿童反馈和家长报告。
- **G3 第 1、2 课连续性**：完成两课内容、状态继承、作品保存和路径复核。
- **G4 教师运行与 QA**：补齐教师卡、错误处理、三学生路径测试、数据导出与文档。

这四个闸门足够，不需要再建立重型治理体系。

**必须现在做**：一套共用任务世界；一套三档支架；内容和引擎分离；教学中间表示；试听证据闭环；第 1、2 课连续状态；真实编译适配器；教师卡；报告生成与人工确认；确定性提示系统。

## 十四、可直接交给 Claude Code / Codex 的长链开发指令

任务名称：九岁儿童 C++ 互动课程第一阶段纵向样片

角色：你是本项目的产品实现负责人、前端工程师、教学交互工程师和测试负责人。你的任务不是重新设计课程方向，而是以最小、可维护的方式实现：1）试听/诊断课；2）正式第 1 课《机器人能量站》；3）正式第 2 课《智能舱门》。

**二、固定产品决策，不得擅自改写**

1. 产品是"诊断自适应的儿童 C++ 互动实验室"，不是传统 PPT，也不是通用在线 IDE。

10. 不开发通用 C++ 解析器。

**五、目标架构**（名称可适配，职责必须保留）：CourseContent（课程、活动、E/S/A 变体、教师卡、提示、证据规则、编译测试）；LessonEngine（活动进度、预测、单步执行、重置、支架切换）；LessonIR（表示变量创建、赋值、输出、比较和分支；同时驱动可视化、聚焦代码、完整 C++ 和预期输出；不解析任意 C++）；Visualizer（变量盒、当前执行行、能量条、条件真假、if/else 分支；SVG/CSS，避免大型游戏引擎）；CompilerAdapter（Mock + Remote，统一请求返回结构，页面不得直接依赖某个供应商）；EvidenceEngine（append-only 事件、支持等级 S0-S4、诊断维度、教师笔记、路径建议、人工覆盖）；ReportEngine（儿童即时反馈、教师能力画像、家长报告、已观察/初步判断/待验证标签、教师确认）；HintProvider（RuleBasedHintProvider 默认；LLMHintProvider 接口，默认关闭）。
